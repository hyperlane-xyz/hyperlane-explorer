# Animated Open Graph previews

The normal homepage and `/message/<messageId>` pages emit `og:video` alongside
existing PNG metadata. There is no separate demo route or illustrative transfer.
Use those ordinary page URLs in an Open Graph validator or a supported chat app.

## Rendering

`pnpm run build` generates `public/og-video/home.mp4` from the existing homepage
artwork. `pnpm run generate:og-video` also generates it for local development.
The file is generated, not committed. The homepage animation loops over five
seconds; the existing artwork remains its poster.

Message videos are generated by `/api/og-video?messageId=<id>` from the indexed
message, registry names/logos, and shared OG warp amount decoder. Unknown senders
remain generic messages, with no invented token amount. Delivered clips replay
receipt at the destination; pending/unknown clips never show a successful receipt.
The displayed status and delivery time remain the actual recorded values.

The renderer rasterizes two keyframes and a small packet, then FFmpeg encodes the
motion. Data/logo requests share a five-second deadline; the native encoder has
the remainder of an eight-second overall rendering budget. Successful videos are capped at 2 MiB, cached for 60
seconds in the CDN and in a bounded instance cache, and support byte ranges/HEAD.
Two concurrent encoders per instance are allowed; duplicate IDs share a render.
Failures are uncached and PNG previews remain available. All subprocess arguments
are fixed filters and temporary paths, with no user-supplied shell commands.

The build copies the platform FFmpeg executable into `.generated/ffmpeg`. The
installer is a build dependency; the Next output trace includes only the single
copied executable and the local logo/font. `pnpm dev` and `pnpm test` also prepare
the executable. Temporary rendering files are removed after each request.
Nothing in the browser executes or downloads the encoder.

## Verification

Check the homepage and an indexed message URL, rather than an MP4 URL, in a
validator. The page HTML must include absolute `og:image`, `og:video`, MP4 media
type, dimensions, and `og:type=video.other`. Missing/unindexed messages use the
homepage video and existing generic image.

Apple Messages and Discord support direct MP4 metadata. Keep the Twitter card as
`summary_large_image` so X can still use the poster. `og:type` follows it because
Discord uses the last applicable layout tag. X Player Cards and Slack video app
integrations are separate and are not implemented here.

Validators may display only poster-based mockups even when the video tags are
present. They do not establish actual inline playback in iMessage or Discord.
Inspect the raw metadata and MP4 responses, and use real clients for playback.
Platform caches may retain old pending status or old tags after a deployment.
